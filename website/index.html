Open source · local-first · MIT

A desktop app for the coding agents you already use.

Claude Code, Codex, Cursor, pi, and Ollama still do the work. Agent UI is the window on your computer where you read a turn, answer what it asks, review the diff, and hand that same chat to a different agent. There is no account. Tokens are billed by the agent or the API you connected.

Download for Windows See a run from the start

The published installer is Windows x64, with automatic updates. On macOS and Linux, run it from source — the same app, in a browser or a desktop window.

  • Chats Pinned, then one group for each folder the agent is working in.
  • The turn The answer, the code, and the files it names. Click a path to open it.
  • Composer Choose the agent and the model, then type the task.

01 · What it is

Three parts. This app is the middle one.

  1. You A task, in plain language, and a folder you are willing to let an agent touch.
  2. Agent UI The chat, the question waiting for you, the diff, and the record of the turn.
  3. The agent Claude Code, Codex, Cursor, pi, Ollama, or any tool that speaks ACP.
  4. A folder The checkout that agent works in. The sidebar groups chats by that folder.

You already have the agent, or you install one. Agent UI finds it on your machine and gives it a chat pointed at a repository. The agent reads that folder, edits files, and runs commands. The app keeps the conversation, shows what changed, and lets you undo the turn.

Chats, settings, and optional memory are files under ~/.agent-ui. Set AGENT_UI_DIR if you want them somewhere else. A CLI such as Claude Code talks to its own service with the login already on that CLI. A model provider you add is called from this machine, with the key you saved.

What it is for

The agent does the work. This is where you read it, answer it, undo it, and hand it on.

03 · A run

From the first click to the handoff.

The same loop every time. The pictures are the real app. The mock agent is standing in, so nothing below depends on a login.

Step 1

Give the chat a folder.

The folder is the workspace. The sidebar groups chats by that checkout and shows the branch, how far ahead or behind it is, and whether the tree is dirty.

A chat can get its own git worktree, on its own branch, stored under the app’s data folder rather than inside your checkout. Two agents can then work on one repository without editing the same files. Removing the last chat that used a worktree offers to remove the worktree too.

Step 2

Choose the agent, then the model.

The picker is three steps: which program runs the loop, which model that program uses, and how much it is allowed to change. A Claude Code chat resumes the claude session. A Codex chat resumes the Codex thread. Switching agents keeps the other one’s session.

Step 3

If it needs a decision, it stops and asks.

A question or a permission request stays above the composer until you answer it. You can skip a question. You can queue a follow-up while a turn is still running, and it sends when the turn ends. The sidebar shows that the chat is waiting, so a run in another chat does not look frozen.

Step 4

Review the diff, then keep the turn or throw it away.

The files a turn changed open beside the conversation. You can read the whole review as one scroll, commit from the chat, or revert a single file. The commit message is written from the diff, in the style of that repository’s recent commits. The first push sets the upstream. Committing on the default branch asks you first.

Every turn in a git folder is bracketed by a checkpoint, including untracked files, and nothing you had staged is touched. One action puts the files back to the way they were before that turn. Checkpoints are on by default. Settings → Chat turns them off.

Step 5

Hand the same chat to another agent.

You were on Cursor. You switch the picker to Claude Code and send the next message. Claude receives a short brief of what it missed: what you asked, which files changed, which commands ran, and which ones failed. Cursor’s session is still there when you switch back. Each agent keeps its own resumable session, tied to this folder.

The brief is saved on the message, so you can read what was handed over. It is a summary, capped, and it leaves out the streamed text — the transcript is already in the chat. Handoff is on by default. Settings → Chat turns the brief off. The sessions stay either way.

Step 6

See the cost, including the turns with no price.

Usage is counted per chat, per model, and per folder, over 7 days, 30 days, or all time. Ollama is free. A model with no public price is counted in tokens and left out of the dollar sum, and the page says how many of those turns there were. A partial total never pretends to be the whole bill.

04 · Also in the workspace

The things you stop doing by hand.

  • Import the history you already have

    Conversations Claude Code and Codex have already had on this machine can be brought in. The next message resumes that CLI session. Nothing is imported until you check the box.

  • Search what was said

    ⌘K or CtrlK matches a chat by its title and by the words in the messages, then opens the chat on that message.

  • Skills and slash commands

    Skills installed on this machine show up in the composer. / lists the app’s commands and the CLI’s own. Each agent receives the invocation it actually understands.

  • Memory, off until you turn it on

    Optional preferences live in markdown files on this machine. The writer only sees what you typed — not files the agent read, and not tool output. It needs a local Ollama.

  • Leave the dev server running

    A turn that finishes leaves the server the agent started, and lists it. A turn you stop still stops that process. Quitting the app while a turn is running takes a held press, so one stray key does not kill an edit.

  • Settle what you are done with

    Settle a chat you have finished, or snooze one until later. The sidebar stays about the work in front of you, and a settled chat can still be opened.

05 · Agents

What you install is the agent.

Agent UI looks for programs already on your machine. If one is missing, the picker says why. Logins for Claude, Codex, and Cursor stay in those tools. Keys you add are for model providers you configure yourself, and they live in settings.json on this computer.

  • Claude Code

    The claude command, already signed in.

    Edits files, runs commands, and resumes the CLI’s own session on the next message. Permission is read-only, edits, or full. Read-only is a deny list the CLI enforces, including in subagents.

  • Codex

    The Codex CLI. codex login, or a model provider that speaks the Responses API.

    The app talks to codex app-server and resumes the original thread. Your ~/.codex/config.toml stays untouched. Permission is read-only, edits, or full. In edits mode, command and file approvals come back to you. A provider you configured also works while you are signed out of ChatGPT, if that endpoint speaks the Responses API.

  • Cursor Agent

    The Cursor agent CLI, already logged in.

    Tools, and a resumable session. The modes are read-only, plan, and full — there is no step between “cannot write” and “can write anywhere”. Changing the mode starts a new Cursor session. The chat in Agent UI stays put.

  • Ollama

    A local Ollama install. If it is installed and stopped, the app starts it.

    Chat only: no tools and no file edits. The app replays the transcript each turn, because Ollama does not keep a session. Models that can think show their reasoning. Usage marks the price as free.

  • Chat (direct)

    Any OpenAI-compatible endpoint. Ten presets, or a base URL of your own.

    The same shape as Ollama: a conversation, no tools, the transcript replayed by the app. Presets include OpenAI, Anthropic, Google, xAI, DeepSeek, Groq, Mistral, OpenRouter, Together AI, and Fireworks. The key stays in settings on this machine.

  • pi

    The pi CLI, plus Ollama or any model provider you added.

    A small harness with tools, over the model you picked. Sessions resume. Commands run as your user — pi has no sandbox. Treat that the way you would a terminal.

  • Any ACP agent

    A command under Settings → Harnesses. DeepSeek Harness and tinyagent are already in the list.

    ACP is the Agent Client Protocol. If a tool speaks it, you add the command and it shows up as an agent, with no change to this app. The process stays up between turns and closes after 15 idle minutes. If the agent cannot reload a session, the new one is briefed with the transcript. An agent installed inside WSL is a setting on that entry, “Runs inside WSL”.

A mock agent is built in. It scripts a turn so you can learn the interface before any of the above is installed.

06 · Your files

Chats are files on this machine.

Move the whole directory by setting AGENT_UI_DIR. Treat it as sensitive: it holds transcripts, and any API keys you saved for a hosted model.

~/.agent-ui/

settings.json
Appearance, which agents are enabled, and keys for model providers you added.
sessions/index.json
The sidebar: titles, folders, which agent ran last.
sessions/<id>.json
One transcript.
sessions/<id>.journal.json
The handoff log. Requests, files, commands, errors. The streamed answer stays in the transcript.
memory/*.md
Optional cross-chat memory. Off by default. One markdown file per category.
imports.json
Which chats were imported, and from which CLI.
worktrees/
Git worktrees the app created for chats that asked for one.

What an agent is allowed to touch

It works in the folder you gave that chat, up to the permission you set. Read-only, plan, edits, or full — whichever that agent can actually enforce.

pi is the exception to the sandbox: its commands run as your user.

Logins for Claude Code, Codex, and Cursor stay in those tools. This app does not ask you to paste them.

07 · Install

Windows installer, or from source anywhere.

Windows

A signed x64 installer on GitHub Releases, with automatic updates. It is large on purpose: it carries a Node.js runtime and serves the app on 127.0.0.1, so there is nothing else to install first.

Download for Windows

Any system, from source

Needs Node.js 20.9 or newer and bun. The mock agent works with nothing else installed.

git clone https://github.com/miskibin/agent-ui.git
cd agent-ui
bun install
bun run dev

Open http://localhost:3000.

Desktop window, from source

Install the Tauri prerequisites, then: 

bun run desktop:dev
bun run desktop:build

desktop:build makes the installer for the machine you are on: dmg, deb, AppImage, or the Windows setup.

08 · Questions

Short answers.

Is Agent UI a model?

No. It is the desktop app around an agent. The model is whichever one that agent calls — Claude, GPT, Gemini, a local Ollama model, or a model behind a URL you added.

Do I need an API key?

For the agents you already use, you need the login those tools already have. Claude Code, Codex, and Cursor keep their own credentials. You add a key only for a model provider you configure under Settings, or for a local Ollama, which needs none. The mock agent needs nothing at all.

Will it change files in my repository?

When you send a task to an agent that has tools, and the permission mode allows it, that agent can edit the folder the chat is pointed at. Read-only stops writes. A turn in a git folder can be undone from the checkpoint taken before it ran. You can also revert a single file from its menu.

What is ACP?

The Agent Client Protocol, a way for an editor — or this app — to talk to an agent. DeepSeek Harness and tinyagent ship as ready-made entries. Any other agent that speaks the protocol is a command, arguments, and a permission policy in Settings.

Can I use it on macOS or Linux?

Yes, from source. bun run dev opens it in the browser. bun run desktop:build makes a native installer on that machine. The file published on GitHub Releases today is the Windows x64 installer.

How is this different from running Claude Code in the terminal?

You get the same Claude Code session either way. In Agent UI that session sits in a sidebar with your other chats, the diff opens beside the answer, a question stays on screen until you answer it, and a turn in a git folder can be undone. Switching the picker to Codex writes Codex a brief and keeps both sessions. If the terminal is enough, you do not need this app.

How is this different from T3 Code or OpenCode?

OpenCode is an agent. It writes the code, and it has its own terminal, desktop, and IDE. T3 Code is a control plane for several agents: desktop, browser, and phone, and a thread can open a pull request. Agent UI is the local record of the work. It runs on this computer, keeps each agent’s session, and is built around reading a turn — the question, the diff, the checkpoint, and the handoff. Pick the one whose job you actually want.

Where does my data go?

Transcripts and settings stay in ~/.agent-ui on this machine. There is no Agent UI account to upload them to. A CLI agent still talks to its own service — Claude to Anthropic, Codex to OpenAI — with the login on that CLI. A model provider you added is called from this machine. Optional memory is off by default, stored as markdown, and the writer only sees text you typed.

Where is the source?

The app is MIT, on GitHub. The conversation view — messages, tools, diffs, the composer — is also published on its own as chat-components, a shadcn registry. Agent UI is the app around those components.
